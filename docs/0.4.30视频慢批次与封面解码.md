# 0.4.30 视频慢批次与封面解码专项

2026-10-27。本轮用户授权最多三种方案，已全部使用；仅采用第三种。源文件只读，不增加解码线程、不修改封面seek、scale、PNG或普通libmpv音频时钟及目标等待。0.4.29已交付的第二排左侧菜单、右侧统一设置布局继续保留。

## 定位与三种方案

固定840路径视频由84源对象的硬链接组成：1/3 MOV、2/3 H263-AMR 3GP，不代表840个独立真实摄像头文件。旧快头解析拒绝非1:1像素比例，因此每个冷3GP封面先启动完整FFprobe。显式GLIMPSE_VIDEO_PHASE_TIMING的六个累计worker阶段计数分别为缓存准备、头/FFprobe、FFmpeg、PNG读回、清理、写缓存；固定数组不增长，默认关闭。诊断中探测平均约47ms、FFmpeg约81ms，PNG读回/写缓存约2ms级，不能把父进程与子进程差值直接称为DLL启动耗时。

方案一：FFmpeg filter_threads=1，12单进程配对中位56.30→56.15ms、8组四进程72.54→70.94ms，PNG一致但收益不足，未写入产品。

方案二：复用已验证索引元数据，native测试曾发现1ms截断，修复后逐像素/版本检查通过，但实际一组前台对照两侧复用次数均0、整屏均5/10。新区域尚无可复用权威元数据，停止未必要的第二组并还原全部方案二生产代码。未完成执行记录和原失败保留，不宣称该分支改善性能。

方案三：非碎片ISO BMFF头中的正数pasp经有界整数换算，显示宽度必须与整数tkhd精确一致；保留旋转、裁剪、异常结构、多视频轨、codec白名单及16384尺寸边界。新增范围还要求影片整秒时长、所有轨道tkhd时长一致，未知结构回退完整FFprobe。五公开样本比较最初发现一个3GP旧65133ms、新65134ms；失败保留，增加上述保守时长回退后，五样本完整RGBA、宽高、整数毫秒时长完全一致，源字节不变。碎片化非方形像素仍回退，避免改变旧streaming读取参数。

## 同程序交替对照

## 正式普通路径与边界

固定照片20组首屏清晰P95新缓存/再访1099.63/818.69ms；120秒冷/再访回调P9518.26/17.92ms、WS573.19/418.08MiB；冻结4K快滑整屏清晰10/10、局部首张10/10、短测WS571.30MiB；视频混合回调P9518.09ms、WS523.11MiB。 视频整屏7/10；前台占比与门槛逐项见同构建performance-gates.json。视频最大回调102.09ms、mpv render最大76.39ms，内部音画时差绝对峰值18.38ms不是实体听感证明。正式结果不被上述成对较好值替换。

三种用满，不追加第四种或新SMB方案。历史网络0.4.20本地副本与SMB/null-output失败仍只作历史证据，不能代替当前GPU网络播放实测。实际系统DPI/多屏、实体键鼠与音频听感、HDR参考、干净断网目标系统、应用开源许可仍未完成。只本地测试，不发布。
