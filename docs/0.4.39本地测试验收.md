# 0.4.39 长 PNG 超过6400万像素加载失败修复

2026-10-28。应用与安装器0.4.39，程序SHA256 `9b742b6646f92a8f16d8f498943c8fd06006e1c0114c7f14adde62e5c5606765`，166项生产输入。仅本地测试；便携/源码/安装实际状态以 `dist/0.4.39-local-test-20261028-streamed-png/delivery.json` 及 `verification/index.json` 为准，旧0.4.38及以下冻结。

## 原因及实现

用户PNG为1741×37528、65336248像素，8-bit RGBA非交错，11520539字节。0.4.38在同一原件的只读副本上复现失败，索引错误明确为“Long PNG requires non-interlaced dimensions within the 64MP budget”。原有流式长PNG已经不分配整张源RGBA，却仍沿用了完整解码的6400万源像素限制，因此此图被拒绝。

仅为单边超过16384的非交错PNG，将流式输入工作量上限单独限定为256000000源像素，单边仍≤1048576；这不是内存配额。逐行解码仍使用32MiB PNG解码预算，输出仍≤16777216像素/64MiB，概览最长8192、可见区域最长4096、每32行取消及前后源fingerprint校验保持。没有全原图RGBA分配、整动画预解码、全库转码或抬高缓存/纹理配额。

普通短PNG、JPEG及其他整图解码仍保持6400万像素、16384单边、256MiB分配限制；交错长PNG等既有不支持范围仍明确报错。长PNG的源上限与输出/解码内存上限分开，保留256MP工作量界限而非无限读取。初次PNG截图缩略图和放大后的原始分辨率区域仍走原显示/颜色路径。
