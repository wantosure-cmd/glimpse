# 0.4.45 视频切换画面交接候选

状态：本地代码与原生验证候选，尚未制作新的正式便携/安装交付。用户真实网盘路径、黑屏时长、手动/自动切换方式待回复，真实网盘效果未验证。当前正式交付仍为0.4.43。

## 现状与原因边界

原有`VideoPrefetch`确实在详情浏览时后台预读下一视频，但它只是一个只读文件缓存预热线程，不是第二播放器或首帧预解码。普通路径最多读头4MiB/尾512KiB，识别为虚拟盘时为头512KiB/尾128KiB；保留文件指纹校验和取消，不保留整视频副本。预热成功不证明视频首帧可立即呈现。

源码检查发现两处等待画面问题：`paint_video`在加载时用整块黑底覆盖已有媒体；播放器加载完成与当前文件首个有效视频帧呈现并非同一事件。另一个启动竞争是刚从A切B时，即使B还没首帧，下一段C的预热也可能启动。上述属于代码证据，不能替代用户网盘黑屏根因的实测。

## 本候选的修改

- 加载等待优先复用当前目标B的版本化封面，保持其原比例；只显示小范围半透明加载提示，不再用整块黑底盖住它。
- libmpv在当前文件已就绪、尺寸有效且有真实新视频帧时才记录首帧；空渲染、旧画面重绘/重复帧不能充当B的第一帧。新视频首帧未确认时不把无效FBO覆盖到封面上。
- 首帧就绪后交由原GPU路径显示；音频时钟、seek、帧目标等待、画质与缓存预算不改。
- B尚未首帧或恢复进度未完成时，暂不预热C；A正常播放后预热B的行为保留。
- 不新增独立封面解码请求，复用列表/底部缩略条已有封面，避免额外网盘读取。若没有B封面且首帧未到，仍可能出现空背景等待；尚未实现双播放器无缝切换，不承诺零间隔。

以已交付0.4.43为代码基线；0.4.44快滑第三方案仍单独冻结，未并入此候选。本次是新用户反馈的视频切换修正，不是第四种快滑性能方案。其续测脚本改为验证冻结源码ZIP及程序哈希，可以在不依赖当前0.4.45工作区字节的情况下恢复原试验。
