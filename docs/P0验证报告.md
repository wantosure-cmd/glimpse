## 本轮工作与问题

已建立并实际运行 Rust 原生验证程序、隔离的 libheif/libmpv C ABI adapter、GPU FBO 渲染、生成测试视频、音频会话电平诊断与便携打包脚本。源码路径和 ABI 来自随包头文件与锁定官方源码。

沙箱内 Cargo 默认离线，初始网络与 CMake 编译器识别失败；获取依赖及原生构建通过授权的本机执行继续。GitHub API 达限，改用官方发行资源页获取文件，未换用未知镜像。

当前生成样本：65 秒可见运动图案与 440Hz 音轨；MP4/MOV H.264+A​AC、AVI MPEG-4 Part2+MP3、3GP H.263+AAC。3GP AAC 不能代替 AMR 测试。

依赖加载采用绝对路径与受限 DLL 搜索。发行目录缺少 runtime 时不会静默回退到开发者源码目录。源码树 target/release/debug 中运行才允许开发依赖目录。

查阅 render.h 后将 mpv 命令和属性读取改为异步：UI/GL 线程不再调用同步 mpv_command/mpv_get_property，避免渲染线程与 mpv 核心互等。属性来自非阻塞事件队列。正式 P3 仍需加入完整 load_id/seek_id 与输入节流。

启动字体从约 20MB 系统字体改为 240,204 字节的 OFL 字体子集，嵌入 exe；许可证与源/输出 hash 在 assets 中。完整任意中文文件名的字体后备将在浏览界面阶段补充。

## 视频与音频证据

每个格式分别运行 `tools/run_p0_smoke.ps1` 的 18 秒原型动作，保存预览、详情和返回预览截图。四次进程均 exit 0，stderr 为空；完整信息见 artifacts/p0-evidence-summary.json。

| 样本 | 解码 | 详情音频峰值 | 预览/返回音频 |
|---|---|---|---|
| H.264/AAC MP4 | NVIDIA nvdec | 约 0.0306 | 均为 0 |
| H.264/AAC MOV | NVIDIA nvdec | 约 0.0304 | 均为 0 |
| MPEG-4 Part2/MP3 AVI | 软件解码，GPU 显示 | 约 0.0289 | 均为 0 |
| H.263/AAC 3GP | 软件解码，GPU 显示 | 约 0.0312 | 均为 0 |

音频由独立本地 C++ 诊断工具读取本程序 PID 对应的 Windows 音频会话电平，不录麦克风、不收集其他应用音频内容。它证明本程序向音频引擎输出非零信号，不能证明物理扬声器接线、系统静音或听感。

资料：[微软音频峰值接口说明](https://learn.microsoft.com/en-us/windows/win32/coreaudio/peak-meters)。

## 性能测量边界

启动程序先创建中文窗口，播放器仍未初始化。20 次热启动原始值在 artifacts/p0-startup-runs.json，当前 build hash 与汇总在 p0-startup-summary.json。外部 WaitForInputIdle 仅证明进程进入可响应空闲状态，内部首次 UI 回调仅为软件计时；二者都不等于严格外部首帧可见测量。不得据此直接宣称全部产品启动指标通过。

早期系统字体版本内部首次 UI 计时曾为 635–1139ms。最终二进制 20 次串行复测：内部首次 UI 回调中位数 314ms、P95 385ms；外部输入空闲中位数 265.94ms、P95 326.35ms。具体原始值和 exe hash 见当前 JSON。这是 P0 空白窗口热启动，不能推广为完整浏览器或冷启动成绩。

空白窗口约 30.57 秒空闲：进程累计 CPU 时间 0.0 秒（测量精度内），工作集 53,137,408–54,194,176 字节，约 50.7–51.7MiB。这不是 5,000 媒体或视频播放内存/CPU 测试。
