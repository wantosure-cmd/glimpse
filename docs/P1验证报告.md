# P1 扫描与索引验证报告

更新：2026-10-17。状态：扫描、索引、递归计数与逻辑视图已实现并通过本机验证；真实权限失败和 junction 回归列在覆盖缺口中。

## 已实现

- 支持图片/视频扩展名分类，明确排除压缩包。
- 自然排序，数字段不依赖整数解析，避免长数字溢出。
- 路径身份使用无损平台编码，Windows 未配对 UTF-16 也不转为有损显示字符串。
- 迭代式递归扫描，只做枚举与 stat，不解码媒体；保留实际所在目录。
- 扫描结果带 generation；取消时可退出有界队列的背压等待。
- 逐目录返回本层图片/视频统计与完成/失败状态。
- 目录完成前先提交其所有批次，为后续可靠索引清理提供顺序保证。
- 跳过 Windows reparse points，避免遍历链接/junction。
- SQLite WAL、bundled SQLite、单写工作线程、schema version 1，主界面不直接访问数据库。
- 重叠根目录复用媒体 ID；按真实 parent 关系查询，避免路径前缀误包含兄弟目录。
- 完整枚举的目录才清理消失文件与子目录缓存；读取失败/取消保留旧缓存并标为不完整。
- 源文件指纹改变时失效元数据与缩略图引用；迟到的旧版本元数据写入被拒绝。
- 目录本层/递归图片视频计数，以及整棵子树完成状态。
- 名称/修改时间/大小升降序、类型分组和筛选、详情跨文件夹逻辑顺序、目录导航历史与滚动锚点。
- 有界扫描队列与 UI 快照，后台空闲时休眠，目录切换立即唤醒并取消旧任务。

P1 阶段结果：18 passed，0 failed，0 ignored；测试执行 0.08 秒。原始输出在项目根目录 artifacts-p1-tests.log。P2 增加布局测试后，库测试共 21 项，见 artifacts-p2-tests.log。

覆盖：自然数字排序、中文与大小写、媒体分类、无损 Windows 路径、三层目录扫描、本层/递归计数、缺失根目录报错、背压时取消、重叠目录 ID 稳定、旧 generation/旧指纹拒绝、失败目录保留、成功目录清理、相似前缀兄弟目录隔离、未来 schema 拒绝且原数据保留、过滤分组排序、详情序列与导航历史。

测试样本均在 target/test-fixtures，未对用户媒体目录做删除/移动/修改。媒体文件只写占位字节，用来测试扫描分类，不作为格式解码证明。

## 5,000 文件 release 实测

测试目录由 tools/make_scan_fixture.ps1 生成：100 个图集目录，每组 38 个 JPG 候选和 12 个 MOV 候选，共 3,800 图片、1,200 视频。内容为占位字节，只验证枚举/stat/索引，不能当作图片解码测试。

命令：`media-browser.exe --scan-report target/perf-fixture-5000 --db target/perf-index.sqlite`。

| 指标 | 首次索引 | 缓存重开 |
|---|---|---|
| 枚举耗时 | 377ms | 278ms |
| 含索引/最终快照总耗时 | 423ms | 319ms |
| 逻辑视图构建 | 62.04ms | 52.01ms |
| 文件/目录数量 | 5,000 / 101 | 5,000 / 101 |
| integrity_check | ok | ok |

两次 sample_ids 相同，图片/视频数量均与生成器一致。原始数据：artifacts/p1-scan-5000-first.json、p1-scan-5000-warm.json。

测试机器沿用 P0 的 Ryzen 7 2700X / Win10 22H2；不是统计性 P95，也不覆盖缩略图和真实大图冷读取。因为排序/视图构建超过一帧预算，P2 使用独立 PrepareService 计算排序和布局，只把结果交给 UI。

## 覆盖缺口

真实 junction 循环与跳出当前根的 junction 已在本项目生成的 target/junction-fixture 验证：根目录一个 JPG 候选，另含指向自身和 5,000 文件测试目录的两个 junction；扫描仅得到 1 文件、1 目录，没有进入链接。原始结果 artifacts/p1-junction-scan.json。没有修改用户目录或删除 junction。

目录权限拒绝的真实 ACL 回归仍未声明通过；失败缓存分支已有自动测试，没有更改用户目录权限。

P2 已开始接入浏览 UI，默认启动现在是浏览器；P0 验证页保留为 --p0 参数入口。完整产品仍需 P2–P5 后续验收。
