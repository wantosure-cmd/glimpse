# P3 混合浏览控制验证报告

更新：2026-10-18。P3 尚未完成全项验收。

本次用户调整：列表预览改为默认有声并自动循环，新增进度控件；旧报告中“列表强制静音”仅描述此前构建，已被本次要求覆盖。详见《UI更新与大图优化.md》。

## 本轮接入

- `src/input.rs` 为统一路由策略；`src/browser_controls.rs` 在 eframe 原始输入 hook 消费事件，先于滚动控件。
- 视频激活区域滚轮每刻度 ±30 秒，像素滚轮累计 100 UI 点才跳转；侧键 ±5 秒。
- 列表其他区域侧键转目录历史；详情视频外区域侧键被消费，不导航。
- Shift+列表滚轮留给页面；输入框、弹出菜单和有焦点的播放器滑杆保留自身输入。
- 左右切换、空格、F11/Esc 也从原始事件入口处理，按键自动重复不触发这些单次动作。
- `SeekQueue` 将待请求目标和观察到的播放位置分开，最多每 80ms 发一次绝对 seek；目标 clamp，旧 load/seek 标识不能确认新目标。
- 详情首次音量 70、有声音；静音与音量写入小配置；当前列表和详情共同使用该偏好，新配置默认有声。
- 列表内容区域停留 400ms 后激活唯一播放器；离开/滚动/失焦/最小化暂停，空闲 2 秒卸载源。
- 保存本次运行的位置，并校验媒体指纹；同一来源从预览到详情复用播放器。

## 修复

1. 目录切换原本只发送 stop、保留 source，返回同一路径会漏掉重新 load。
   现统一 unload 清空源和缓存，并清理控制器绑定与 pending seek。
2. 详情每次打开强制取消静音/恢复 70，现使用独立、持久化的详情偏好。
3. 普通 seek 不更改播放/暂停状态；恢复历史位置时才使用“先暂停加载、发出定位后播放”的路径。
4. 播放器以 FILE_LOADED 和所观察的路径核对 ready，避免新源加载时直接采用旧位置/时长。
5. mpv 本地 UNC 路径保留服务器前缀；不再把 `\\?\UNC\...` 简单裁剪为相对文本。
6. 首轮真实回归发现 unload 清空全局属性缓存后，未变化的 mute/volume 不会再次通知，
   导致重开详情读到空值。现仅清理文件属性，保留播放器全局选项；失败原始记录保留在
   `artifacts/p3-before-property-cache-fix/`，修复后完整回归需重新通过。

## GIF 动画专项（2026-10-17）

`src/animation.rs`：单后台线程，最新请求替换，generation 取消，输出 channel 容量 2；
不调用 collect_frames，不按动画长度累计 RGBA 内存。满队列时工作线程最多额外持有一个待发送帧。
每次读文件和每帧边界检查取消，逐帧复核源指纹；关闭/换媒体时丢弃旧 token 结果并释放源句柄。

使用现有 image 0.25.10 的帧合成处理透明度与 disposal；
gif 0.14.2 从已有传递依赖改为显式锁定依赖，只扫描压缩块元数据确认循环数及 ICC，不解码并存储整段动画。
无循环扩展播放一遍，Finite(n) 播放 n+1 遍，Infinite 持续循环。
有意义的帧时长照常使用，0 时长以 100ms 处理，最小调度时长 10ms，避免无间隔空转。

`src/gif_viewer.rs`：单一纹理更新，按帧截止时间唤醒；积压时只上传最后一个到期帧。
后台未就绪时等待 worker 唤醒，不对已过期截止时间无条件持续重绘。
关闭详情立即清理动画，最小化/遮挡暂停时钟；长时间无 UI 回调后恢复，不追赶隐藏期间数小时的帧。
动画纹理计入浏览器原有 256MiB 纹理淘汰预算。

明确的资源上限：源文件 256MiB，画布最多 8,388,608 像素、单边 8192；
image 解码分配限额 128MiB，元数据扫描单帧限额 32MiB。超限显示具体失败信息，仍可浏览其他媒体。
这些是实现保护限额，不是对整个进程工作集的实测保证；巨型 GIF/异常压缩数据另报失败，不隐瞒为完整动画支持。

本轮库测试 32 项通过，另有 1 个显式运行的 fixture 导出工具默认跳过；
覆盖 RGB/100-350-80ms、有限与无循环、源字节不变、队列背压取消、过期指纹、画布预算，
以及局部帧的 Previous/Background disposal 和透明度。
默认应用测试 4 项通过，1 项真实视频封面测试仍沿用前述显式执行规则。
