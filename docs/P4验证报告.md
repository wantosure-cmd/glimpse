## 文件变化监听

- 锁定 `notify 8.2.0`，本机原生后端实测为 `ReadDirectoryChangesWatcher`。
- 监听当前根目录的后代以及父目录自身；父目录通知用于发现根目录删除和重建。
- 500ms 安静期合并通知，持续通知最长 2 秒触发一次失效提示。
- 应用只保留一个待切换根目录、一个待交付通知和固定大小的去抖状态；
  不把每条系统通知积压到应用的无界事件队列。
- 根目录监听 epoch 独立于重新扫描 generation。旧根回调不能刷新新根。
- 通知只触发重新扫描，文件数、目录数、删除和 fingerprint 由扫描和 SQLite 核对。
- 监听建立后再次请求核对，覆盖第一次扫描与订阅之间的空窗。
- 程序数据目录从产品扫描和监听事件中过滤，避免缩略图被重新导入及触发缓存反馈。
- 刷新按钮和从失焦到激活时也请求核对；扫描期间合并为一次后续扫描。
- 原地刷新保留界面、历史、勾选和滚动锚点；新快照剔除已消失的勾选。
  当前详情消失则关闭，文件指纹变化则重新加载；旧播放器源版本失效时卸载。
- 监听失败显示警告，继续允许手动刷新。

系统通知不能作为百分百可靠的唯一来源，网络文件系统可能没有通知。
上述刷新回退与父目录监听依据 [notify 官方说明](https://docs.rs/notify/8.2.0/notify/)。
网络盘、权限拒绝和通知溢出的产品实测仍未完成。

## 回收站后端与真实文件验证

`src/trash.rs` 新增独立 Windows adapter 与专用工作线程。本节记录此前仅后端阶段；当前 UI 接入见文末。
锁定 Windows API 绑定 `windows 0.62.2`、`windows-core 0.62.2`，依赖已写入 Cargo.lock。
非 Windows 明确返回未实现，不提供永久删除回退。

- `TrashRequest` 携带媒体 ID、根目录、规范化绝对路径、size/mtime 指纹。
  仅处理根目录内普通文件；路径变更、重解析点或指纹变化时拒绝。
- 使用 `IFileOperation`，显式设置 `FOFX_RECYCLEONDELETE`、`FOFX_ADDUNDORECORD`、
  `FOFX_EARLYFAILURE`、`FOF_NOERRORUI`、`FOF_SILENT`、`FOF_NOCONFIRMATION`、
  `FOF_NO_CONNECTED_ELEMENTS`。共享目录不降级到本地永久删除。
- `PreDeleteItem` 通过 COM 回调再次检查目标路径与指纹，并要求
  `TSF_DELETE_RECYCLE_IF_POSSIBLE`；没有回收标志时返回失败，阻止操作。
- `PostDeleteItem` 保存每项 HRESULT 和真实回收项路径；缺少回收项或操作被中止时不报告成功。
  产品代码没有 `remove_file`、`del` 或其他永久删除实现。
- STA COM apartment 和 native 对象由工作线程管理。命令队列容量 1、结果队列容量 16，
  返回逐项 Item 和最终 Finished，失败一项后继续处理后续项；重复 ID/路径批次拒绝。
  关闭服务时停止尚未开始的项；已经进入 Shell 的单项操作不强杀。
- 文件占用、权限和回收站不可用错误提供中文原因及原始错误码。

接口依据 [SetOperationFlags](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperation-setoperationflags)
与 [PreDeleteItem](https://learn.microsoft.com/en-us/windows/win32/api/shobjidl_core/nf-shobjidl_core-ifileoperationprogresssink-predeleteitem)。
回调标志检查有测试，但真实禁用回收站、超配额、外接盘、共享盘和 Win11 尚未实测；
不能据此把完整 A14 标为通过。

## Delete 与回收站 UI 接入（2026-10-18）

本轮完成 `src/browser_trash.rs`、原始 Delete 路由及媒体右键回收入口。列表只处理所选，详情只处理当前项；无选中不操作。`KeyLatch` 消费按住期间的重复事件，释放后才能再次触发。输入框、菜单、回收进度和失败窗口不会穿透到媒体删除。成功后优先下一项，再上一项，最后关闭空详情；失败项保留并给出路径和原因，可解除占用后重试。

删除前，缩略图服务在同一把锁中阻止目标媒体的新任务和排队任务，等待正在执行的解码/媒体工具返回；GIF 取消等待实际流解码函数返回；播放器使用带独立请求标识的异步 stop 回复，随后才观察本次 `idle-active`，旧属性事件不能确认新请求。该阶段最多等待 20 秒，超时或出错不向 Shell 提交任何回收请求。三类释放确认均为真后，才交给专用 STA 回收线程。

播放器 6 次 MP4/AVI 专属复制测试含已载入和载入中取消，释放确认后 Windows 独占打开成功；GIF 背压取消、缩略图阻止新任务后等待释放的专用测试通过。`artifacts/p4-player-release.json` 是无窗口播放器测试，不能当 GPU/UI 证明。

成功回收结果按媒体 ID、路径及指纹条件从 SQLite 删除，并对本轮未结束的扫描设置版本墓碑，避免旧枚举批次重新插入；下一次扫描清除墓碑，允许系统恢复的同版本文件重新出现。新扫描 generation 过滤旧快照；计数从仓库重算，不手动重复递减。对应数据库幂等/旧批次/恢复重新出现测试通过。

真实静态 Shell verb 通过 Windows ShellExecute 启动复制到中文/空格目录中的程序，六次请求全部转交同一原生进程；实际窗口后端经历最小化再恢复，激活不重复导航。临时盘符只映射到专属一图目录。旧安装清理保留新安装的三个键，新安装清理移除它们；测试盘符和测试键均在结束时核对移除，四份媒体哈希不变。背景菜单验证的是实际注册命令的展开执行，未宣称模拟了 Explorer IContextMenu 点击。

窗口隐藏后 eframe 不运行界面绘制，故 IPC/回收结果与退出计时移到 `App::logic`，不依赖可见窗口重绘；详情隐藏暂停保存逻辑暂停意图，列表仍使用悬停条件。实际视频隐藏和回收期间 IPC 的更广组合尚待验收，不能用目录最小化测试替代。
