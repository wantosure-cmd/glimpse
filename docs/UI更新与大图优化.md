# 2026-10-18 原生界面更新

用户确认采用 Ant Design 视觉规范，保留 Rust/egui 原生窗口及 libmpv GPU 视频渲染。未接入 React、WebView 或 Ant Design 的 JavaScript 组件库。

## 行为调整

- 深色表面、Ant 主蓝色、6–8px 圆角、统一按钮高度与间距；工具栏合并路径导航、媒体筛选、排序、预览大小与多选状态。
- 单击媒体进入详情，左上角勾选；Ctrl 点击切换选中、Shift 点击范围选择、Ctrl+A 全选、Ctrl+C 复制所选路径、Esc 清空选择。
- 右键非选中媒体会切换到该项；右键已选项保留批量选择。菜单提供详情、图片 1:1、视频从头播放/静音、同目录选择、批量路径复制、资源管理器定位和媒体信息。
- 列表悬停播放使用声音偏好，新配置默认有声；离开视频、滚动或失焦仍暂停并静音，避免多个视频同时发声。列表播放 `loop-file=inf`，详情播放仍保持原先的末尾停止行为。
- 列表活动视频叠加暂停、声音切换、时间和可拖动进度条，宽卡片另显示音量。控件点击排除媒体打开，拖动期间维持当前预览。
- 视频详情点击媒体范围外的空白返回；标题按钮、缩放按钮、播放器按钮及滑块不触发空白返回；打开详情的同一帧不立即关闭。

## 大图路径

- JPEG 使用 jpeg-decoder 0.3.2 在解码时选择 1/8、1/4、1/2 或完整尺寸，然后缩至目标预览大小。保留源尺寸、EXIF 方向及 ICC 转 sRGB。特殊 JPEG 像素类型仍走原解码路径。
- PNG 缓存仍无损，改用 Fast 压缩和 Sub 过滤，减少后台写缓存耗时；缓存键升级避免复用旧策略的结果。
- 图片详情优先使用已在内存中的预览，按窗口实际像素、显示缩放和查看缩放请求 512–8192 档清晰图，不再始终先解码 8192 档。
- 保留原先的有界工作线程、可见区优先、纹理预算和源文件只读约束。
- 缩小解码主要改善 JPEG；HEIC、PNG 等仍受各自解码器限制。没有实现超大图分块，超过既有预算的图仍报错。

## JPEG 实测

机器为本机 Win10 22H2、Ryzen 7 2700X、16GiB 内存；release / Rust 1.98.0。使用程序生成的 8000×6000 RGB JPEG，三轮顺序读取同一文件，目标均为 512×384。不是实际用户摄影图集，也不是全库冷启动测试。

| 指标 | 原路径 | 缩小解码路径 |
|---|---:|---:|
| 解码加缩放中位耗时 | 404.62ms | 183.04ms |
| 三轮解码加缩放范围 | 390.21–430.96ms | 176.59–211.72ms |
| PNG 写缓存中位耗时 | 2.09ms | 2.46ms |

该样本解码加缩放约快 2.21 倍、耗时减少 54.76%。新解码中间图为 1000×750，再缩至 512×384；没有把它当成实际进程峰值内存测量。PNG Fast 在本样本未体现加速，不宣称其有确定收益。原始结果为 `artifacts/ui-large-jpeg-benchmark.json`，包含专属源路径及 SHA256；测试检查源字节未变化。
