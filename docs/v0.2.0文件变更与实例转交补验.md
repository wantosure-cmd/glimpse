## 普通桌面权限下跨进程转交

使用普通非受限Windows令牌运行两个0.2.0实例。测试作用域随机，A/B各一份生成JPEG，使用独立数据目录；不联系、注入或关闭用户旧实例，不改注册表、ACL或令牌。

最终验证：客户端 `forwarded=true`、server_pid与实际服务进程一致；服务端received≥1，准备结果root为B中文空格路径、media=1；服务端与客户端退出码均0，源副本hash不变。原始caller/server的restricted均false，报告范围仍明确不包含物理Shell菜单或Win11。

此前受限SID的拒绝记录保留为历史，不再把它描述成当前所有会话都无法转交；本次证明的是隔离作用域的真实两进程转交，不冒称已操作用户主实例。

### 汇总脚本失败的定位与修复

较早两次测试程序均已转交并退出，PowerShell汇总仍占CPU。增加阶段日志后定位到汇总对象创建之后；字段级只读重放停在client_stdout的JSON转换。PowerShell5.1的Get-Content读取字符串带有PSPath/PSDrive/PSProvider扩展属性，ConvertTo-Json会展开额外对象；降低深度的一次输出仍达113445324字节，不是合格的小型报告。

将stdout/stderr改为System.IO.File.ReadAllText纯文本，令牌记录显式规范为简单字段，保留进程句柄和有界等待。最终同条件重新运行约13秒完成，报告4933字节，stdout/stderr都是字符串，退出码和转交/源hash断言全部保留。没有把先前卡住的汇总直接标成通过；只停止了核对命令行的专用汇总/重放脚本，测试媒体程序均已退出，用户旧程序保持运行。

原始成功报告 `v020-isolated-instance-clean.json`，阶段日志与client/server原始输出均留档。异常的超大反射报告只留本机，不复制到交付，避免带入无关系统元数据。
