将现有合法JPEG EXIF6、HEIC、H.264 MOV、MPEG4/MP3 AVI、H.263/AMR 3GP分别复制到独立生成的多层目录，路径包含中文、空格、👩‍🚀和组合重音é，完整路径长度介于354–374个UTF-16单元，均超过260；逐项长度与病例名见原始JSON。

这证明这些编码在上述超长路径下工作，不表示全部编码、目录链接或长路径批量回收均通过。emoji出现在真实文件路径并被正确打开。另已查看长路径MOV的实际详情截图：文件名中的组合emoji未正常显示；这是已观察到的文字显示缺陷，不能标成字形通过。路径I/O兼容通过与字形UI未达标分别记录，后续需修复字体回退/字形覆盖。

## GIF 原生动画

三份合法生成GIF分别为无限循环、有限重复和单次播放，当前便携版使用专属副本及数据目录。原生显示红/绿/蓝帧，中心像素核对通过；无限循环至少序号8且未结束，有限重复最终序号5并结束，单次最终序号2并结束。每个源复用同一纹理；此2×1夹具账面纹理8字节，不能外推大型GIF的峰值内存。

按已有50ms容差核对每帧声明时长，最大实际回调间隔误差16.535ms；判据未放宽。程序退出码0，三份公共源和三份副本hash一致。不是物理显示呈现时序、系统失焦或所有GIF disposal组合的穷尽证明。

## 真实 NTFS 拒绝与恢复

普通Windows权限下，只对新建且带标记的target专用子目录临时加当前用户ListDirectory拒绝规则，两个PNG均是公共样本副本。三阶段均使用同一持久SQLite索引：

1. 初始扫描2项，子树完整。
2. 实际目录枚举确实返回UnauthorizedAccess；当前Release记录os error5，父和被拒绝子目录标为不完整。保留此前2项索引，不把暂不可读内容错误清空。
3. finally恢复原始SDDL，严格核对完全一致；之后扫描2项、无错误，integrity_check=ok，公共源与两份副本hash不变。

这是实际拒绝访问数据路径，尚不是原生GUI权限提示命中验收、共享盘权限或磁盘满场景。只操作专用测试目录ACL，未改用户真实目录或系统全局权限。

首次测试脚本在设置ACL之前失败：PowerShell5.1 Get-Content未明确UTF-8，按ANSI读取带中文的JSON而解析失败。原始失败日志保留；改为File.ReadAllText(..., UTF8)后，在新目录重新执行以上三阶段通过，没有放宽应用断言。
