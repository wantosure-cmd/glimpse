# 掠影 Glimpse 0.3.0 本地测试版

本轮在 Rust / egui / libmpv 原技术栈上修改，不迁移界面框架，不改变用户媒体文件。交付版本由 0.2.0 增加至 0.3.0，保留旧包。

## 使用方式

- 列表页顶部操作栏的空白区域支持拖动窗口，双击可最大化/还原；字标原有拖动保留。路径框、导航和窗口按钮继续独立响应操作。
- 详情页双击图片、视频或组合中的图片，返回列表。视频单击仍控制播放/暂停；空格控制当前视频，轮播状态下则统一暂停/继续轮播。
- 详情页右键 → 自动播放：选择「逐张播放图片和视频」或「成组播放图片」。自动播放期间右上角显示模式和暂停/继续入口。
- 逐张播放遵循当前排序和筛选后的媒体顺序，图片默认停留 3 秒，视频播放完继续下一项。手动浏览时原有视频播放结束策略仍保留。
- 成组播放支持 2–5 张，默认 3 张。连续图片按真实横竖比例组合，自动选择横排、竖排或分层布局；视频单独播放。组不跨文件夹或视频，尾组不足设定数量时展示剩余图片，不重复补图。
- 组合默认铺满画布，保持图片比例并居中裁切；取消「组合图片铺满画面」可完整显示图片，允许留黑边。这只改变显示方式。
- 右键菜单中可调图片停留时间 1–60 秒、每组数量和是否循环。偏好保存到本地；启动应用不会自动开始轮播。
- 轮播按键和左右箭头按当前页切换；成组模式下切换整组。仍可从底部缩略图定位，右键组合图片的「单图查看」退出组合查看该图片。
- 图片显示后才计时；加载、暂停、菜单/设置、文件操作、窗口失焦或最小化期间不累计图片停留时间。关闭详情停止轮播。失败视频显示错误后跳到下一项，避免无限停留。

## 实现与资源控制

`presentation.rs` 负责有序分页、布局及计时，`browser_presentation.rs` 负责接入详情、右键菜单和播放状态。布局最多枚举 32 种有序方案，选择裁切较少的方案，保持原始图片比例。

组合图片按实际单元尺寸请求缩略图，单张最多 2048 像素档位；下一组最多预取 5 张 1024 像素缩略图，优先级低于当前画面，并在 GPU 缓存接近上限时停止预取。继续共享原有 256 MiB 纹理上限，不一次性解码整个目录。视频沿用现有有界预取机制。

另补齐 egui 0.37 的单色 Emoji 字体回退，避免带 Emoji 的文件名缺字；字体与许可文本按固定哈希验证并随包交付。不承诺所有新 Emoji/ZWJ 序列均合成为单个彩色符号。

## 验证记录

最终结果及二进制身份以本交付目录 `verification` 内报告为准。原生受控输入测试使用独立生成图片和视频，不操作私人图库；截图来自实际 OpenGL 画面。受控窗口拖动请求不能等同于物理鼠标移动窗口验证。

本轮首次原生测试发现单图双击响应问题后进行了修复；初次失败报告保留，不计为最终通过。历史 0.2.0 的局域网、5000 项目录、Win10 系统观察仍保留历史构建身份，不能视为 0.3.0 全量重验。Win11、不同设备物理输入、多屏 DPI、干净系统及真实 iPhone HDR/杜比视界验收仍未完成。

应用源码开源许可尚未决定，本轮仅交付本地测试包；依赖许可文本随包保留。
