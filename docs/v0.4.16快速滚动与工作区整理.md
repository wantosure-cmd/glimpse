# 0.4.16 图片加载与工作区整理

保留原有 Rust/egui、GPU 视频、图片比例、方向和 ICC 颜色处理、渐进预览，以及每帧两张纹理上传。结果 FIFO 容量仍为8、GPU预算仍为256MiB、解码像素复用上限仍为128MiB；不扩大预算。

JPEG 的模糊预览和清晰缩略图复用同一次缩放解码的中间像素；更大尺寸会重新解码，不能把小预览放大冒充原图。清晰图完成后释放 JPEG 中间像素，屏上纹理和磁盘缓存保留。同一媒体正在解码时，其他线程先处理别的媒体。

初次 JPEG 小预览携带后续清晰缩略图尺寸，在不超过1024档时按该尺寸做缩放解码，再从同一中间图生成64像素模糊图和清晰图，避免两个阶段各读原文件。临时 JPEG 像素在原有128MiB总预算内再单独限32MiB，清晰图完成即释放；超大档不提前解码超大中间图。沿用原有FIFO/背压、每帧两张上传与视口任务优先级，撤回实验中过度丢弃结果和激进上传的方案。

原生检查另发现200%应用缩放/小窗口的设置页越界，已约束左右区域滚动范围，保留原本纵向分类及全部入口。0.4.12–14实验候选的原始失败/性能记录保留，不作为最终通过；最终测试和性能见本版verification。内部回调和纹理就绪采样不是物理屏幕呈现或普遍提速比例。
