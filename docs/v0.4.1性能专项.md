# 掠影 Glimpse 0.4.1：缩略图流水线性能专项

2026-10-22。本版保留 Rust / egui / libmpv GPU 视频方案，以及 0.4.0 的收藏、清理、复制剪切、400% 音量、中英文和拖动多选。没有修改界面密度、缩略图画质或原文件。

## 改了什么

1. **缓存维护退出解码关键路径。** 旧实现每个解码线程完成约 30 项就同步枚举、读取属性并排序整个缩略图缓存，包括命中缓存的情况。现在交给单独的可取消维护线程：启动后延迟维护，后续按实际新写入数触发，合并请求，至少间隔两秒。重新浏览已缓存文件不会每 30 次命中就再全盘枚举。
2. **有界增加 JPEG 并发。** 保留两个通用图片解码线程和两个视频任务线程；根据逻辑处理器数，额外增加零至两个只处理不超过 2048 桶尺寸的缩放 JPEG 线程。本机 16 逻辑核额外两个。HEIC / PNG / TIFF 和原尺寸详情请求不进入额外通道，避免大原图并发解码造成内存突增。
3. **补齐可解释的加载指标。** `--load-metrics` 诊断区分柔化预览与目标尺寸清晰图，记录可见尺寸待定数、缓存命中、解码和维护次数及累计时间。正常界面不显示诊断、不持续重绘；累计任务时间不是 CPU 时间。

原有的优先可见内容、先尺寸后排版、渐进预览、下一媒体有界预载均保留。原像素缓存 128 MiB、GPU 纹理预算 256 MiB、磁盘缓存预算 2 GiB 和缓存键版本均未提高；磁盘维护是异步过程，预算并非每次写入后的瞬时硬上限。

## 测量方法与边界

- 前版 0.4.0 SHA256：`82dcce3e3ac50fb504f009f241d0b495085e37238a3d267020c3875e294faef8`。
- 本版 0.4.1 SHA256：`61230b8ac05919b76b0f2bd58197cf89e33b1f2a300756c56f8eec59d2d02624`。
- 同一台 Win10 / Ryzen 7 2700X / 16 逻辑核 / 16 GiB / RTX 2070 主机，Release，先前版再新版顺序运行；最终对比期间没有并行编译或打包。操作系统文件缓存未清空，不能称冷启动或冷磁盘实测。
- 大图：32 份相同的合成 8000×6000 JPEG，每张约 2.4 MB；每版本五次，使用独立空应用缓存。测进程启动至前 12 张目标 512 桶 PNG 全部生成的外部时间；不是屏幕上最后一个像素实际出现的时间。
- 大库：5000 份有效生成媒体（重复 JPEG / PNG / HEIC / 视频），每版本 20 次空库启动、120 秒新应用缓存滚动、120 秒同缓存回访滚动、预热后 30 秒空闲。滚动视口 3840×2160，egui 缩放 150%。源文件测试前后逐项哈希核对。合成重复图库不能代表真实图库的全部格式、尺寸或损坏情况。
- 帧间隔为原生回调间隔，不是物理显示 FPS；工作集只包含主进程，不是整个 FFmpeg 子进程树或 GPU 显存。启动外部 input-idle 与内部首次 UI 回调的起点不同，不做相减解释。
- 尚未重测路由器共享目录、CloudDrive2、真实 SSD 极限吞吐；本次不能承诺把磁盘读满。解码、缩放、缓存及小文件访问都可能先于磁盘吞吐成为限制。

## 测量结果

结果以交付包 `verification/v041-performance-comparison.json` 及其原始数据为准。

| 指标 | 0.4.0 | 0.4.1 | 说明 |
| --- | ---: | ---: | --- |
| 前 12 张大图清晰缩略图生成中位数，5 次 | 1959 ms | 1580 ms | 缩短 19.35% |
| 首个柔化预览中位数，5 次 | 771 ms | 790 ms | 基本持平，未改善 |
| 5000 文件，新缓存滚动回调 P95 | 17.75 ms | 17.82 ms | 基本持平 |
| 同缓存回访滚动回调 P95 | 17.57 ms | 17.67 ms | 基本持平 |
| 新缓存滚动主进程峰值工作集 | 227.68 MiB | 232.08 MiB | 增加 4.40 MiB |
| 回访滚动主进程峰值工作集 | 203.07 MiB | 212.80 MiB | 增加 9.72 MiB |
| 纹理峰值 | 256 MiB | 256 MiB | 预算未提高 |
| 外部 input-idle P95，20 次 | 198 ms | 210 ms | 小幅变慢；不是首帧时间 |
| 内部首次 UI 回调 P95，20 次 | 292 ms | 262 ms | 起点与上一行不同 |
| 预热后空闲 CPU，30 秒、归一整机 | 0.019% | 0.010% | 均很低，不将差值解释为稳定收益 |

两个版本均无预览失败，5000 个生成文件测试前后哈希一致。十轮大图的前 12 张柔化及清晰 PNG 共 **240 份逐字节相同**。本版回访 120 秒内有 12811 次流水线缓存命中、366 次解码、7 次后台维护（合计约 123 ms）。回访仍有解码，因为滚动继续触及此前未缓存内容；不是宣称所有媒体已经热缓存。

结论限于本次数据：**大图成批生成更快，滚动保持原有水平，内存略增**；本次没有证明磁盘吞吐、首个预览或所有视频起播都加快。新旧每版本各一轮大库测试、五轮大图测试，尚不足以给出跨设备统计结论。

视频另测同一份合成 H.264 / AAC 文件，每版本三次，原生格式检查全部通过（包括声音、跳转、返回列表和源哈希）。从播放器 load 请求到首个就绪 GL 渲染，中位时间前版 **206 ms**、本版 **211 ms**，基本持平。这个指标不包含 load 前的播放器初始化，也不是鼠标点击至显示器出画面的延迟；不能代替 580 个视频的局域网目录起播测试。详细数据见 `verification/v041-video-performance-comparison.json`。
