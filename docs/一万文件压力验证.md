# 一万文件压力验证

更新：2026-10-19。当前交付 Release SHA256 `94eecb9ef6329f87e6f62725ca4a7a3102989e6a27559d1e656947d207d1ea15`，与上一轮格式和5,000文件测试相同。程序二进制没有修改。

## 样本和测量方法

从已用于格式验证的合法媒体复制生成新专属目录，共10,000文件、200个分组：9,180 JPEG、600 PNG、200 HEIC、20 MP4。每个文件生成后核对源哈希，测试结束再逐文件核对，10,000项均未改变。不是10,000张不同的高分辨率摄影原片，也没有写入或删除真实资源库。

机器沿用《交付构建格式与性能复验.md》中的Win10/Ryzen2700X/16GB/RTX2070/D盘NVMe。样本在同一D盘；启动时使用新的索引与空缩略图缓存。OS文件缓存已经被生成和哈希核对预热，不是重启后冷启动。独立扫描先运行，再用原生浏览器创建自身新索引并滚动。

这轮未见工作集或纹理无限增长，测得工作集小于600MiB、回调P95小于20ms。上述阈值是诊断指标，不代替真实显示呈现和物理滚动流畅度验收。纹理账面字节不包含全部GPU驱动开销。最终最大滚动位置215,986.44点、累计解码8,401次、缓存命中3次：已索引10,000项，但没有声称逐张看完所有卡片，解码计数也不等于唯一文件数。

`src/thumbnails.rs` 将每轮待处理请求截断到256，清理旧视口队列，结果通道容量8且工作线程3。此为代码边界说明，本轮未新增运行时队列深度采样，不把静态边界当作逐帧队列观测。
