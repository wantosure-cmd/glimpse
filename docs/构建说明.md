# Windows 构建与本地打包

应用许可证暂不决定；只生成本地测试包。源码中没有应用 LICENSE。本说明不表示第三方二进制已完成公开发行审核。

跨电脑先看 [项目交接](项目交接.md)，运行 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/handoff_preflight.ps1 -CheckCargoCache`。本节以下保留了一些历史命令和计数；当前交付与测试身份以交接文档及当前verification为准。仅复制文件夹不包含机器级Rust/MSVC、Cargo依赖缓存和个人AppData。

## 工具链

- Windows 10/11 x64；Rust 1.98.0 MSVC（rust-toolchain.toml 固定版本）。
- Visual Studio 2022 Build Tools 的 C++ 工具、Windows SDK；本机使用 MSVC 14.44.35207、SDK 10.0.26100.0。
- 打包脚本使用 PowerShell 7 和 Python 3.12 标准库，无需 NSIS、Node、Electron 或浏览器运行时。
- 如重编译 libheif/libde265，另需 CMake 和锁定源码。字体子集已包含在 assets，普通编译不需要 fontTools。

## 从源码包重建应用

1. 完整解压源码 ZIP。在源码根目录执行 `cargo fetch --locked`。首次获取开发依赖需要网络；Cargo.lock 锁定具体版本与 registry 校验和。
2. 用已交付便携 ZIP 恢复同一套原生运行库：

   ```powershell
   python -X utf8 tools/restore_runtime.py C:/path/media-browser-portable.zip --sha256 这里填SHA256SUMS中的便携ZIP哈希
   ```

   此步骤只读取本地 ZIP，不联网。脚本核对 ZIP、每个文件以及源码中已锁定的 runtime/media-tools 哈希；拒绝覆盖内容不同的现有运行库。
3. `cargo build --release --locked --offline --bin media-browser` 构建主程序，再执行 `pwsh -File tools/build_setup.ps1`，单独将安装器及其 Rust 依赖以 `-C target-feature=+crt-static` 编译到 `target/setup-static`，避免安装器依赖未安装的 VC runtime。模板尚未附带载荷，不能直接安装。
4. 主程序和静态CRT安装器均构建后，用 `python -X utf8 tools/package_local.py --tag 我的新包目录名 --runtime-directory vendor/runtime` 复用已验证的完整运行库；新应用交付必须先升版本。输出目录必须不存在。也可先用 `pwsh -File tools/package_preview.ps1` 建立staging，但会额外复制一份大运行库。脚本检查安装器无动态MSVC CRT导入，并将主程序直接导入的vcruntime140.dll放在exe同目录；只放在runtime子目录不能满足Windows启动加载器。

安装器没有运行期网络请求；它是 Rust 原生 exe 加尾部文件载荷，按长度和 SHA256 流式复制。它与浏览器使用同用户主实例互斥体，安装期间不接收目录转交；不强制终止运行中的程序。

开发依赖全部到位后，Cargo 可以 `--offline` 构建。此源码 ZIP **不是 cargo vendor 全平台离线依赖包**，不承诺在没有 Rust 工具链和 Cargo 缓存的断网机器上编译。离线“运行”和首次离线“编译”是不同交付范围。

## 从锁定上游重建图片解码库

执行 `python tools/fetch_p0.py`、`python tools/fetch_heif_sources.py` 获取并校验各自清单中的固定归档，然后 `pwsh -File tools/build_heif.ps1` 编译 libde265/libheif。这些下载步骤首次需要网络。libheif 必须静态绑定其 HEVC 解码插件配置并动态依赖本包的 libde265.dll，不能以没有 HEVC 解码器的空壳替代。

libmpv 目前使用锁定的官方 GPL 预编译包；外部 FFmpeg 使用锁定 Gyan 二进制。它们的完整对应源码、所有传递依赖及构建环境尚未整理为可公开再分发的源码集，见《第三方依赖与许可证.md》。不能将应用源码重建等同于已经从源码重建了全部第三方运行库。

## 验证命令

- `cargo test --locked --offline`：含真实 Shell 回收测试，仅使用程序生成并标记的专属副本，不操作真实资源库。受限沙箱可能需要允许普通用户 Shell/管道能力。
- `python -X utf8 tools/verify_local_install.py dist/包目录/media-browser-setup-local-test.exe --registry`：在工作区 target 下新建专属目录，验证安装、HEIC/MOV、运行中拒绝、非空/目录联接拒绝、卸载与文件保留；注册表测试遇到已有本地测试版记录会拒绝执行，不覆盖。
- `tools/run_*_smoke.ps1`：原生界面合成输入与真实回收/临时系统集成测试，不能视为完整物理键鼠验收。

安装器尚不支持覆盖升级；先卸载旧版再装。没有自动更新、系统服务、全局默认文件关联或遥测。未来 Mac 需要实现平台适配并原生编译，不能复制 Windows exe 直接使用。

## 云盘与旋转回归

- `python -X utf8 tools/run_edit_cloud_smoke.py`：仅在 target 下生成的 JPEG/PNG 副本上批量旋转、GPU 截图核对及自定义快捷键验证。
- `python -X utf8 tools/run_edit_cloud_smoke.py --cloud-root "U:/其他/syl小米手机"`：只读扫描目标目录、选最小 MP4 播放/快进/音频测量，前后核对所测源文件哈希。云盘需要挂载驱动可用，此测试不写回云盘。
- 系统集成和回收 UI 脚本默认改为 `dist/browser-preview/media-browser.exe`；可显式传 `-ExecutablePath`。同构建核对应检查每组报告中的 exe_sha256，不能混用 Debug 和 Release。
- 新套件总计 63/3 时，证据汇总器参数为 `verify_trash_native.py --expected-lib-tests 53 --test-log 新日志 --output 新报告` 和 `verify_p4_current.py --expected-tests 63 --test-log 新日志 --backend-evidence 新报告文件名 --output 新汇总`。保留旧默认值供历史日志核对，不把旧日志覆盖成新结果。


## 可选隔离离线依赖探针

`tools/diagnostics` 新增静态CRT的opengl-probe工具，使用CMake/VS2022构建，仅用于测量实际WGL版本，不是应用渲染回退。`tools/run_sandbox_probe.py` 可在本机已有Sandbox可用时启动禁网专属来宾，读取当前pathfix包，测试包内依赖/安装卸载并收集真实UI失败。来宾无需Python/编译工具。工具既不会启用可选功能，也不会把Sandbox的OpenGL1.1失败当成通过；当前环境及复现命令见《Sandbox离线依赖验证.md》。
