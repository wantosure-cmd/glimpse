# 界面文案集中管理

2026-10-19，对应规格“默认中文界面，所有界面文案集中管理，预留翻译”。本次只调整自有界面/状态/错误文案的组织方式，不更改默认显示文字、媒体处理逻辑或设置格式。

## 当前实现

- 唯一维护入口为 `assets/i18n/zh-CN.json`，共 345 条消息、376 个引用，覆盖 29 个生产模块，含浏览器、详情、回收/旋转、目录/监听、媒体解码错误和安装/卸载提示。
- `src/ui_text.rs` 由 `tools/ui_catalog.py` 生成。应用/安装器编译时宏展开为原有静态字符串字面量，运行时不读取 JSON、不查表、不联网，不要求用户安装 Python。
- 调用使用稳定编号，如 `media_browser::ui_text!(msg_fcf8b4bff0df)`。编号不随翻译修改；可在 JSON 中按中文文本查到对应编号。新增消息也可选用有含义的 ASCII 编号。
- 61 条格式模板仍由 Rust 编译器检查参数与格式类型。模板来自宏时须显式传入命名变量，迁移已补齐原先隐式捕获的命名参数。
- 原有可见英文技术错误也收拢到目录，默认值仍原样保留。用户文件名/路径、SQL/IPC/解码器协议键、图标与比率、诊断样本名、第三方原始错误不作为翻译资源，不能为了翻译而改动它们。
- 当前发布只提供中文。支持生成其他完整目录的编译时变体，尚没有运行时语言选择设置；不把翻译预留当作已完成其他语言的翻译/排版验收。

## 修改与验证

编辑 JSON 的 `text`，保留编号。`source` 和 `original_literals` 是迁移/格式参数基线，不是运行时第二套文案。新条目至少包含 `text`、`source` 和 `format_template`。

```powershell
python -X utf8 tools/ui_catalog.py generate
python -X utf8 tools/ui_catalog.py check
cargo check --bins --locked --offline
python -X utf8 tools/verify_ui_catalog.py
```

新增示例：

```json
"selection_count": {
  "text": "已选 {n} 项",
  "source": "已选 {n} 项",
  "format_template": true
}
```

```rust
// 可执行程序中：
format!(media_browser::ui_text!(selection_count), n = count);
// 共享库自身使用 crate::ui_text!(...)；无参数标签直接 ui.label(...宏调用...)。
```

增加新消息后，可以手工放入目录并使用编号；`adopt` 是有备份的辅助迁移，不代替人工区分协议、文件名与真实界面文字。`migrate` 只允许首次建库，避免重复覆盖。

未来新增完整英文目录，可运行 `generate --catalog assets/i18n/en-US.json`，随后 `check --catalog assets/i18n/en-US.json` 并重新编译；恢复中文运行默认 `generate`。可以使用 `--rust-output` 输出到专用测试目录，避免修改发布用中文目录。

## 已完成的验证与待测范围

`artifacts/ui-text-catalog-verification.json`：全部 345 条原字面量与生成宏由实际 Rust 编译执行逐条相等检查；另用独立 en-US 测试目录验证标签和带变量错误模板，删除必需命名参数时生成器拒绝，生产中文目录哈希不变。

`check` 检查目录与生成 Rust 一致、消息编号有效、已审查的自有中文/英文技术文字没有遗漏。新增文案仍需代码审查，不能把任何扫描器当成能自动理解所有字符串用途。

首轮完整测试遇到导出宏工具属性和旧 rlib 缓存的问题：已移除多余格式化属性，没有禁用编译器未来兼容性检查；共享 target 后只可逆备份本项目库的缓存指纹并强制重建，未清空含样本的 target。源码包验证工具也已采用同一策略，防止旧库被误当成本次源码的构建结果。失败日志保留，最终测试结果以 `ui-text-tests.log` 为准。
