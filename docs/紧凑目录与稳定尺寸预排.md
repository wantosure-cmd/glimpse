## 本轮行为

1. 固定/浮动侧栏宽度收紧至220逻辑像素；列表层级缩进由18减为8，每侧最多40且受可用宽度约束。目录条高度由38减为30，缩小按钮和间距，保留细竖线、选择、折叠及定位。统计独立靠右，长名称不会把统计挤走。
2. 文件夹新增直属子文件夹数，含空目录，不递归累计孙目录；过滤图片/视频不改变这个数。侧栏图片/视频仍沿用该树的递归数量，文件夹数字仅指直属目录。扫描未完成时随结果更新。专项夹具根目录3个、123下2个、456下1个，空目录0个。
3. 预览大小160–1600，最右端明确强制单列，不依赖屏幕宽度；8K逻辑布局也已验证。拉回后恢复多列。
4. 未知尺寸不创建1:1假比例媒体格，先显示“正在读取尺寸…”行。按每个排序分段的已知尺寸前缀追加卡片，未知项最多预排24个；视口邻近最多调度64个纯元数据任务/帧。已布局前缀不会因后续项尺寸返回而变形。
5. 纯尺寸任务不解码像素、不上传纹理、不写像素缩略图缓存。JPEG读头并应用EXIF方向；视频先ffprobe，尺寸任务不生成封面；HEIC使用libheif seekable reader API v1，64KiB读缓冲、累计回调请求64MiB上限，避免尺寸阶段整文件Vec。正常像素解码仍遵守原有资源上限。
6. 清晰图出来前继续沿用柔化小预览。纹理源尺寸与布局一致才显示；采用新布局时保留可见媒体锚点，无媒体则保留目录标题锚点。修复初轮发现的“元数据返回推走刚定位目录”：新定位持续跟随，用户主动滚动/按键/鼠标按下即释放定位锚点。

这是消除“未知尺寸方格突然撑开”的方案，不承诺扫描新增项目、窗口尺寸改变、排序或过滤时完全不重排。云盘首次尺寸读取仍可能等待网络；单个排序前缀的慢文件会延迟该段后续项显示，不为了快而重新放入假比例格。只存宽高等小元数据，内存成本远低于提前解码全目录大图。

## 文件体积的成本答复

本轮没有增加体积显示。把文件大小整数相加几乎不消耗算力，主要成本是枚举目录及取得文件系统元数据。本地盘通常较轻；CloudDrive2挂载可能需要远端元数据请求，受网络、缓存和驱动策略影响。可在扫描时顺带累计并缓存，后续文件变化增量更新；不要滚动时反复遍历，不需要读取文件内容。若“所有文件”含子目录，还要首次遍历整棵树；若仅本目录则只统计直属文件。不能把逻辑文件大小等同磁盘实际占用、压缩后占用或云端传输流量。
