## 最终行为

- 详情贴近窗口上下边缘，仅保留紧凑单行信息栏；完整路径通过文件名悬停查看，图片的适应、原尺寸和旋转保留。
- 图片与视频共用底部横向缩略图栏。顺序与当前筛选、分组、排序一致，单击切换、当前项蓝框高亮。仅处理可见缩略图，沿用异步解码、文件版本检查和缓存上限。
- 两端各留半屏空间。第一张从正中间向右排列，切换后当前项居中；最后一张最多向左移动到中间。左右两端不循环。
- 媒体区左右的上一张/下一张按钮在鼠标进入媒体区时显示，离开后隐藏；按钮独立叠加，不改变媒体和缩略图布局。
- 视频进度条单独占一行，接近媒体区全宽；播放、时间、声音和全屏在紧凑下一行。仍使用原 GPU 渲染，不产生每文件播放器。
- 视频详情默认播完后按当前序列播放下一个视频，跳过图片，末尾停留且暂停。设置及详情右键菜单可选择重播当前视频或停在结尾；正常退出保存设置。列表视频仍保持循环。
- 已完成视频再次手动打开从头开始，未完成视频仍记住运行期间位置。
- 详情右键：上一张、下一张、返回、复制路径、资源管理器定位、回收站；图片另有适应/原尺寸/旋转，视频另有声音、播放暂停、从头播放及结束策略。复用原旋转和回收站服务，不提供永久删除。
- 视频详情点内容外的空白返回；控制栏、缩略图空隙和右键菜单不属于返回空白。

## 失败记录与边界

初轮发现侧边按钮误移动主布局游标，缩略图栏叠到媒体中部；现已改用独立子 UI 叠加。初轮还发现完成视频重新打开立即触发下一段，现记忆 EOF 位置为零。原始失败保留在 `artifacts/detail-redesign-v1`。

后续旧布局测试在暂停拖动阶段遇到窗口最小化/尺寸变化，未满足专项检查，保留于 `artifacts/detail-redesign-v3`；没有把该轮算通过。最终紧凑布局使用新设置重新运行，完整专项通过。测试中对拖动使用跨帧按下/释放事件，窗口变化时最多重试三次，仍以实际播放位置及 pause 属性断言结果。

回收站和旋转本轮复用现有服务及原生单元回归；没有在真实资源库操作，也不把“菜单出现”当成每个菜单操作的端到端验收。Win11、真实物理输入完整矩阵、干净 GPU 离线目标系统、10-bit iPhone/HDR 专业颜色等原有未验项继续保留。旧构建性能数值不视为当前构建性能证明。
